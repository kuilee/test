What is an enum in Java, and why is it useful for modeling a finite set of values?

What Is an Enum (Max 2)

An enum defines a fixed set of named constant instances of a type.


Enum constants are type-safe alternatives to string or int constants.


Each enum constant is a singleton instance of the enum type.


Enums can declare fields, constructors, and methods in addition to constants.

Why Useful (Max 2)

Restricts values to a known domain at compile time.


Improves readability compared with magic strings or numbers.


Enables exhaustive handling in switch expressions when all constants are covered.


Reduces invalid-state bugs caused by unexpected literal values.

What is the difference between Collectors.toList() and Stream.toList()?

Collectors.toList() (Max 2)

Collectors.toList() is used with collect and returns a List.


The API contract does not guarantee the List’s concrete type, mutability, serializability, or thread-safety.


It has been available since Streams were introduced and is widely used in older codebases.


Relying on mutability of the result is unsafe because that behavior is not guaranteed.

Stream.toList() (Max 2)

Stream.toList() is a terminal operation that returns an unmodifiable List.


It is a more concise alternative to collect(Collectors.toList()) when an unmodifiable snapshot is desired.


Attempting to structurally modify the result throws UnsupportedOperationException.


Prefer Stream.toList() when you want a guaranteed unmodifiable list of results.

Question
What is a Stream pipeline in Java, and how does it process a collection of data?

What Is a Stream Pipeline (Max 2)

A Stream pipeline is a sequence of operations that process elements from a data source declaratively.


It typically consists of a source, zero or more intermediate operations, and a terminal operation.


Streams do not store data themselves; they convey elements from a source through operations.


Pipelines express what should happen to the data rather than how to iterate over it manually.

How It Processes Data (Max 2)

Intermediate operations build a pipeline of transformations that is executed when a terminal operation runs.


Elements are processed through the pipeline, often one at a time, without requiring an explicit loop.


The terminal operation produces a result or a side effect and completes the pipeline.


This style makes filtering, mapping, and aggregation more concise and readable than imperative loops.

What is the difference between composition and inheritance in Java, and when would you prefer one over the other?

Key Differences (Max 2)

Inheritance models an is-a relationship by extending a superclass.


Composition models a has-a relationship by holding references to other objects.


Inheritance tightly couples a subclass to its parent’s implementation and hierarchy.


Composition allows behavior to be reused by delegating to collaborator objects.


A class can extend only one superclass but can compose many objects.

When to Prefer (Max 2)

Prefer composition when you need flexible reuse without committing to a rigid class hierarchy.


Prefer inheritance when a true subtype relationship exists and polymorphic substitution is required.


Composition is often safer for evolving designs because dependencies can be swapped or reconfigured.

Question
What is the difference between structural and non-structural modifications in Java collections?

Structural Modifications (Max 1)

Structural modifications change the size or internal structure of a collection, such as adding or removing elements.


Structural modifications can invalidate iterators and may cause a ConcurrentModificationException when a collection is modified during iteration.

Non-Structural Modifications (Max 1)

Non-structural modifications do not change the size or structure of the collection.


Examples include replacing an existing element (for example, using List.set()) or updating the state of an element already stored in the collection.

What is the purpose of Optional in Java, and when is it appropriate to use?

Purpose (Max 2)

Optional is a container that may or may not hold a non-null value.


It makes the possibility of absence explicit in method return types.


It encourages callers to handle missing values intentionally rather than relying on null.


It provides APIs such as map, flatMap, filter, and orElse for safe presence handling.

When Appropriate (Max 2)

Appropriate as a return type when a value might legitimately be absent.


Not recommended as a field type or method parameter in most APIs.


Should not replace every nullable reference; use it where absence is part of the contract.


Prefer clear domain modeling of absence over returning null from lookup-style methods.

Question
What is the difference between method overloading and method overriding in Java?

Overloading (Max 2)

Overloading defines multiple methods with the same name but different parameter lists.


Which overloaded method to call is resolved at compile time based on argument types.


Overloading can occur within the same class and does not require inheritance.


Return type alone is not enough to distinguish overloaded methods.

Overriding (Max 2)

Overriding redefines an inherited instance method with the same signature in a subclass.


Which overridden method runs is resolved at runtime based on the actual object type.


Overriding supports polymorphism through dynamic dispatch.


The overridden method typically keeps a compatible return type and cannot narrow checked exceptions arbitrarily.

Question
What is the difference between throw and throws in Java?

throw (Max 2)

throw is used to raise an exception at runtime.


It appears inside a method body with an exception instance, such as throw new IllegalArgumentException(…).


After throw executes, normal control flow stops and the exception propagates unless caught.


throw is about producing and signaling a failure.

throws (Max 2)

throws is used in a method declaration to declare checked exceptions the method may propagate.


It informs callers that they must handle or further declare those checked exceptions.


throws does not itself raise an exception; it documents and enforces the method’s exception contract.


Unchecked exceptions do not need to be declared with throws.
